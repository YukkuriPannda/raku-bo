# 仕様: 草グラフウィジェット

実装: `mobile/widgets/SpendingHeatmapWidget.tsx`（登録名 `SpendingHeatmap`）
共通の仕組みは [spec-widget-common.md](spec-widget-common.md)

日別の支出を GitHub の草グラフ風に見せる 2×1 のウィジェット。
配色と集計はホームタブの草グラフと同じ `mobile/lib/heatmap.ts` を使う。

## 表示要素

- **15列 × 7行** のマスだけ。文字・凡例・月ラベルは無い（`buildMonthLabels()` は
  存在するがウィジェットからは使っていない）
- 列は連続した7日の区切りで、**日曜境界ではない**
- 対象は**直近105日**（`WIDGET_ROLLING_DAYS = 105`）。表示枠は105マス
- マスは角丸4・間隔1で、領域いっぱいに比率で配分する
- 背景色の指定は無く、ランチャーの背景が透ける

### 色

| 状態 | 色 |
| --- | --- |
| 範囲外（データ無しの日） | `#F3F4F6` |
| レベル0（支出0） | `#EBEDF0` |
| レベル1 | `#C6E8D1` |
| レベル2 | `#7CC79A` |
| レベル3 | `#3B9E63` |
| レベル4 | `#1B7F4F` |

レベルは**表示中105日の最大額に対する比率**で決まる（≤25% が1、≤50% が2、
≤75% が3、それ以上が4）。額の絶対値ではないので、最大額が変われば同じ支出でも
色が変わる。

**データが無いとき**は105マスすべてが範囲外色 `#F3F4F6` になる。

## タップ

ウィジェット全体が `OPEN_URI` で `rakubo://history` を開く（履歴タブ。
[spec-history.md](spec-history.md)）。ネイティブで完結し JS は動かない。

## 保存されるデータ

`refreshHeatmapWidget()`（`calcBalance` の末尾から毎回呼ばれる）が作る。

1. 105日分に足りない過去月を `GET /transactions?month=...` で取得する（**毎回通信する。
   キャッシュしない**）
2. 現金かつ建て替えでない取引を端末ローカル日付で日別に合計する
3. 105日分を「基準日 ＋ [日数オフセット, 合計] の配列」に圧縮して SecureStore に保存する
4. 2048 バイトを超える場合は古い日から削って警告を出す

取得に失敗したときはコンソールに出すだけで、前回のキャッシュが残る。

## 既知の挙動

- 定期更新では値は変わらない。105日の再集計はアプリを開いたときだけ
- `resizeMode` が `none` で min = max なので、サイズは変えられない
- 建て替え（`is_advance`）は常に除外する（ホームの草グラフと同じ）
